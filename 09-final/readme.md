# DREAMING: An Experimental Archive of Dreams

# Project Ideas

## Concept

A polished experimental archive composed of seven digital objects developed across the semester. The project treats dreaming as a space where creative coding, sleep research, historical theory, geography, personal memory, and conversation can coexist.

## Object Direction

The final work can be understood as an experimental observatory of dreaming: each digital object offers a different method of approaching the same subject, while the archive interface allows visitors to move between subjective, scientific, historical, geographic, and participatory forms of knowledge.

## Spatial Experience

The homepage is a full-screen dream landscape with eight floating letter/number bubbles. Each bubble opens a browser-like window containing one part of the archive. Visitors construct their own route through these fragments rather than moving through a fixed sequence of pages.

## Interaction

The archive uses pop-up windows opened and manipulated within the main board canvas to represent different layers of unconsciousness. Dream canvases can be disturbed or rotated, data can be hovered, maps can be explored, and the Dream Composer allows visitors to write, assemble, and talk through a dream.

# Digital Objects

## Digital Object

The seven core digital objects are: 2D Spatial Canvas, 3D Spatial Canvas, Build Your Dream, Dreaming Trajectory, A Relational Structure of Dream Theory, Nightfall, and the Dream Guide embedded within the Dream Composer.

Together, these objects approach dreaming through different forms of visual, spatial, historical, geographic, computational, and participatory exploration.

## Spatial Composition

The archive organizes the seven objects as a shared spatial environment rather than as separate webpages. The floating bubbles and browser-like windows create a common navigation system, while each object retains its own internal structure and mode of interaction.

## Motion

Clouds, grain, floating bubbles, popup transitions, canvas animation, and the final cursor-following bubble trail create a continuous ambient field. Individual computational objects provide their own local motion and behavior.

## Technical Character

The final archive combines p5.js, Three.js, D3.js, Mapbox GL, Firebase-backed dream contributions, standalone composer assets, CSV/JSON/GeoJSON datasets, and custom SVG letterforms.

The Dream Composer is embedded as an iframe so its CSS and JavaScript remain isolated from the archive shell.

## Data and Content

The archive should be understood through the content it exposes rather than through implementation history. Text, geometry, datasets, relationships, visitor contributions, and computational rules are treated as materials that shape the experience.

## Visual Language

### Color Palette

The main environment keeps the Dreamcore palette of faded blue, lavender, peach, translucent white, and liminal darkness. Individual digital objects may maintain their own palettes inside their windows when their subject or method requires a different visual character.

### Typography

The archive uses IBM Plex Mono and Space Mono for technical and interface language, with Bagel Fat One used around the Dreamcore navigation. Hand-crafted SVG glyphs replace rendered bubble letters for the final title treatment.

## Layout

The homepage functions as a spatial board rather than a conventional webpage. Floating letter/number bubbles establish the primary navigation, while browser-like windows allow visitors to open, move between, and manipulate different archive objects without leaving the shared environment.

## Atmosphere

The archive should feel exploratory rather than instructional. Its visual identity comes from the relationship between space, typography, interaction, and the subject of dreaming.

The experience should preserve a quiet sense of curiosity, uncertainty, and discovery, inviting visitors to stay with the archive rather than rush toward a single result.

## Website Components

### HTML

The HTML establishes the archive as a distinct digital environment with a clear title, short explanatory text, navigation system, interactive surfaces, and supporting controls or information.

Individual digital objects should remain identifiable within the larger archive while maintaining their own internal structures.

### CSS

The CSS establishes the relationship between the individual objects and the wider archive. The shared Dreamcore environment provides continuity, while local visual systems can become more analytical, tactile, or spatial when the subject requires it.

The CSS should also support the spatial behavior of the archive, including floating elements, browser-like windows, transitions, and layered interfaces.

### JavaScript

The JavaScript makes the archive experiential rather than simply navigational. Data should become something that can be explored, visual studies should respond to visitors, and archive content should appear through interaction rather than through a conventional sequence of pages.

The behavior of each object should reflect its underlying computational logic: spatial canvases should respond to manipulation, networks should expose relationships, maps should reveal geographic variation, and text should remain material that can be rearranged or explored.

## Design Principles

### Archive

Treat each digital object as an artifact within a larger archive rather than as an isolated webpage. The shared environment should create continuity between objects while allowing each one to have its own identity and method of exploration.

### Participation

Where appropriate, let visitors contribute, manipulate, remix, or reinterpret the material. Participation should feel like part of the experience of dreaming rather than like using a conventional application.

### Computational Character

Keep the underlying rule system visible through the behavior of each object. Particles should behave like particles, networks should reveal relationships, maps should reveal geographic variation, and text should remain material that can be rearranged or explored.

### Interaction

Let interaction reveal the object rather than explaining everything in advance. Visitors should be able to discover relationships, behaviors, and meanings through exploration.

### Ambiguity

Preserve ambiguity where ambiguity is part of the subject. The archive does not need to resolve dreaming into a single interpretation; different objects can offer different ways of approaching the same phenomenon.

### Cohesion

Make each project recognizable as part of the Dream Archive while allowing it to develop its own visual and computational identity. The archive should feel like one environment containing distinct artifacts rather than seven identical interfaces.
